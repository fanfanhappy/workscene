# ADR-0002：窗口匹配评分与歧义门槛

- 状态：已采纳（M1，2026-11-21）
- 关联：PRD §4.3 FR-006、§18.1 红线一、评审 R1

## 背景

「恢复」的本质是把快照里的窗口重新对应到当前桌面上的窗口。Windows 没有稳定的窗口持久标识：HWND 在进程重启后失效，标题会随文档变化，类名不唯一，进程 PID 每次启动都不同。

PRD 只写了原则（"多条件匹配、歧义时不操作"），没有给出可实现的评分。评审 R1 指出这是全产品成败点。

## 决策

匹配实现为纯函数 `score_window` + `match_window`（`src-tauri/src/restore/matcher.rs`），权重如下：

| 特征 | 权重 | 说明 |
|---|---|---|
| 可执行文件全路径（忽略大小写）一致 | 0.55 | 主依据；路径不可读时退化 |
| 进程名一致（仅当路径不可读） | 0.22 | 受保护进程的降级路径 |
| 窗口类名一致 | 0.25 | 与路径同时命中才可能过门槛 |
| 标题归一化后完全一致 | 0.15 | 归一化=去标点/空格、小写、保留中日韩 |
| 标题互相包含 | 0.07 | 部分分，防止「差一个字符」被当成同一个 |
| 目标矩形与候选矩形重叠率 | ≤0.05 | 只作打破平局，不单独决定 |

判定规则：

- `score < 0.70` → 不操作（`Skipped`）；
- 前两名都 ≥ 0.70 且分差 < 0.08 → **歧义，跳过**（`Skipped` + `ambiguous`）；
- 同一恢复任务内，已被占用的候选从池中移除（一个窗口不会被移动两次）。

## 后果

- 只靠标题相似的窗口永远不会被移动；两个完全相同的记事本窗口会被跳过而不是随机选一个（有单测）；
- 路径 + 类名同时命中的前提下，标题只影响排序，不影响是否可行；
- 代价：**同一 exe 的多窗口场景**依赖「按可执行文件补齐实例数」的逻辑，否则多个目标会抢同一个窗口。当前实现会在恢复前按快照里每个 exe 的窗口数补齐实例（上限 3/次）。

## 未决

- 权重与门槛来自纸面推演，**没有用真实应用集调过参**；评审 A5 要求的 10 应用 × 3 场景基线尚未建立，因此这组数字应视为初值而非结论。
- `reuse_policy`（`reuse_if_matched` / `always_launch` / `reuse_or_launch`）在代码里固定为「能复用就复用」，尚未暴露配置。
