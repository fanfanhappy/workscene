# ADR-0004：自动快照的指纹、节流与保留策略

- 状态：已采纳（M5，2026-11-21）
- 关联：PRD §3.4 / FR-012 / R6、评审红线二（"自动快照不能每次窗口变化都写库"）

## 问题

"环境有没有发生有意义的变化"如果不定义，自动快照只有两种坏结局：

- 按精确矩形比较 → 用户拖一下窗口就多一条，一天能攒出几千条；
- 完全忽略矩形 → 移动窗口不被记录，历史里看起来"什么都没变"。

## 指纹定义（`data::workspaces::fingerprint`）

对每个窗口生成一段字符串，排序后整体哈希（`DefaultHasher`）：

```
可执行路径(小写) | 窗口类名 | 显示器标识 | 横向位置桶 | 宽x高 | 纵向位置桶 | 显示状态
```

关键取舍：

| 字段 | 处理 | 理由 |
|---|---|---|
| 窗口标题 | **不入指纹** | 标题含文档名/未保存标记，抖动大，且属于隐私内容 |
| 位置 | 按 **40px** 分桶 | 允许小幅抖动，但真的移动会被记录 |
| 尺寸 | 精确值 | 尺寸变化通常意味着用户意图 |
| z 序 | 不入指纹 | 层序变化频繁且无信息量 |
| 显示状态 | 入指纹 | 最大化/最小化是用户可感知的变化 |

相同指纹 → 跳过；不同指纹 → 还要过下面的节流。

## 节流与保留

- **最小间隔** 180s（`AUTO_MIN_INTERVAL_MS`）：两次自动快照之间至少隔 3 分钟，避免用户拖窗口时连续写入；
- **保留** 每个工作空间最近 20 份自动快照（`AUTO_KEEP_PER_WORKSPACE`）；
- **淘汰只针对** `snapshot_type = 'auto' AND is_protected = 0`：手动快照、初始快照、恢复前保护快照永不自动删除；
- 淘汰时同时删除对应 payload JSON 文件（不留孤儿）。

## 自动快照的归属

自动快照必须属于某个工作空间，否则无法参与恢复与比较。规则：

- 用户在「恢复中心」成功执行一次恢复后，该工作空间写入 `app_settings.active_workspace`；
- 后台任务每 60s 检查一次：没有激活空间、或该空间 `auto_snapshot_enabled = 0` → 不做任何事；
- 有激活空间 → 扫描桌面 → 走指纹+节流 → 需要时写入。

这避免了"桌面上开着两个工作空间的应用，快照该算谁的"这种无法回答的问题。

## 后果

- 自动快照是**尽力而为**的：应用未运行时不会记录，切走工作空间后会停止记录；
- 指纹用 `DefaultHasher`，**跨版本不稳定**，因此只用于同一次运行内的去重比较，不写进任何需要长期一致的判断；
- 标题不入指纹意味着"同一窗口换了文档"不会被自动快照记录 —— 这是刻意的隐私取舍，用户仍可手动快照。

## 未决

- 保留数量目前是常量，未接设置页（PRD §12.1 的 Storage 分组）；
- 自动快照没有"仅空闲时"判断，用户正在操作时也可能触发（只是不会弹窗、不抢焦点）。
