## 一、总体结论

**PRD 的 16 条功能需求：12 条完整落地，2 条部分，2 条按非目标放弃。**
UI 规范的 7 个页面中 6 个有独立实现，`Applications 适配器中心` 并入设置页（功能可用、形态不同）。

真正缺的是两块**文档承诺过、代码里没有**的能力：

1. **`project` 与 `terminal` 资源类型**（FR-002 明列 terminal；FR-010 是项目上下文恢复）；
2. **自动快照的窗口事件触发**（PRD §3.4 说"窗口事件 + 低频校验"，现在只有 60s 轮询 + 180s 节流）。

其余缺口都是环境限制（双屏/开机启动未实机验证）或工程卫生（取消无测试、无更新器/签名）。

## 五、缺口清单

### 功能缺口（文档承诺、代码没有）

1. **`project` / `terminal` 资源类型**（FR-002、FR-010）。目前用户只能用 folder + IDE 打开方式凑近效果，且 Terminal 只能靠 launch_args 手填。
2. **自动快照的事件驱动**（PRD §3.4）。现在 60s 轮询 + 180s 节流，意味着"快速切走再切回"这类短时变化不会被记录；同时也没有"变化合并窗口"的显式实现（节流只是时间下限）。

### 验证缺口（实现有、没证明）

3. **双屏 / 混合 DPI**：代码路径齐全，本机单屏。
4. **开机启动**：注册表写入在本环境被拒。
5. **托盘左键/菜单点击**、**全局快捷键实际触发**：只能验证进程状态，点不了。

### 工程缺口

6. **取消功能无测试**（`RESTORE_CANCEL` → run 状态 `cancelled` 的映射没有单测）。
7. **`duplicate` 不复制快照**：语义未定（是有意还是遗漏）。
8. **无更新器、无代码签名、无崩溃转储/诊断包导出**。
9. **`workspace_import_preview` 已就绪但 UI 未接入**（当前靠导入后的 warning toast 提示）。
10. **无 L3 适配**：VS Code 工作区、Terminal profile、浏览器实例语义都没有。

## 六、建议

**若目标是"能自用"**：现在的完成度足够，把验证清单里 D 段（双屏）跑完即可。

**若目标是"能交付给别人"**，按顺序补：

1. `project` / `terminal` 资源类型（FR-002/010）——这是文档里唯一还缺的"功能承诺"，工作量约 1 天（item_type 白名单 + 恢复时的打开方式 + 编辑器入口 + 2 条测试）；
2. 自动快照事件触发（窗口事件 → 去抖 10s → 合并 30s）——约 1 天，能显著提升"重启后还原度"；
3. 取消与导入的单测补齐（半天）；
4. 更新器 + 签名 + 诊断包（1–2 天）；
5. 双屏/DPI 实机验证（依赖硬件）。
