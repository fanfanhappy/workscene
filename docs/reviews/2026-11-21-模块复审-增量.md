## 二、问题清单

### P1-1 快捷槽按"列表位置"绑定，删除工作空间后会指错

```rust
pub fn restore_workspace_by_index(app: &AppHandle, index: usize) {
    ... .and_then(|list| list.get(index).map(|w| w.id.clone()))
```

`Ctrl+Alt+2` 恢复的是"列表第 2 个"，而不是"我绑定的那个"。删掉一个工作空间后，原来按 3 的空间变成按 2，用户按快捷键会**恢复到错误的空间**——而且他会以为是快捷键失效，不会想到空间被换掉了。

**建议**：把 slot 持久化到工作空间（`workspace_items` 同级新增 `hotkey_slot` 列，或 settings 里存 `slot -> workspace_id` 映射），托盘/设置页显示"Ctrl+Alt+2 = 写作"，而不是位置。

### P1-2 1873 行新代码，0 条新测试

最该测而没测的四处：

### P2-1 启动时恢复 = 登录即拉起应用

`startup_workspace_id` 在启动 3.5 秒后自动执行完整恢复，包括 `relaunch_missing`。叠加"开机启动"后，行为是：**登录 → WorkScene 启动 → 自动打开该空间的一堆软件**。

这是合理的产品能力（"上班开机一把到位"），但界面上只是一行下拉框。建议文案写清后果，并在首次启用时二次确认。

### P2-2 专注模式会动用户的其它窗口

它把"不属于本空间的可见窗口"全部最小化。虽然：

- 默认关闭；
- 报告里写明"已自动最小化 N 个非本空间窗口（未关闭任何软件）"；

但用户第一次遇到会发现"我的微信不见了"。建议首次启用时弹一次说明，或提供"只最小化上一次恢复记录里的窗口"这种更保守的选项。
