# WorkScene 实机验证清单（持续更新，初版 v0.1.0）

- 目的：把"只有我这台单屏机器验证过"的部分补上，尤其是**双屏 / 混合 DPI**。
- 用法：从上到下勾，每项都写了「怎么判定」和「失败时给我什么」。
- 标记说明：
  - ✅ **已在本机验证**（单屏 3840×2160 @150%）
  - ⚠️ **未验证**：代码已实现，但没有实机数据

建议顺序：**A（安装）→ B（自检）→ C（单屏功能）→ D（双屏/DIP，重点）→ E（快照与崩溃）→ F（系统集成）**。
预计 60–90 分钟；D 段单独留 20 分钟。

## A. 安装与基本形态

| # | 操作 | 期望 | 状态 |
|---|---|---|---|
| A1 | 在**干净环境**（虚拟机或另一台机器）双击 `WorkScene_0.1.0_x64-setup.exe` | 安装完成，开始菜单/桌面出现 WorkScene；首次启动若缺 WebView2 会自动引导安装 | ⚠️ |
| A2 | 首次启动 | 窗口 1280×840 居中；侧栏 5 项（总览/工作空间/现场捕获/恢复中心/历史快照）+ 底部设置 | ⚠️ |
| A3 | 再双击一次 exe（单实例） | 第二个进程立即退出，只把已存在的窗口拉到前台；任务管理器里只有 1 个 `workscene.exe` | ✅ 本机验证 |
| A4 | 点窗口右上角 × | 窗口消失但**进程仍在**（托盘里还有图标），不是退出 | ✅ 本机验证 |
| A5 | 左键点托盘图标 | 主窗口重新显示并获得焦点 | ⚠️ 未点击验证（只验证了进程存活） |
| A6 | 右键托盘 → 退出 WorkScene | 进程结束，托盘图标消失 | ⚠️ |

> A5/A6 在沙箱里没法点托盘菜单，请重点看这两项。

**验收**：A1/A2/A5/A6 全过 → 安装形态可用。

## B. 自动自检（不做判断，看输出 PASS/FAIL）

在安装目录或源码目录执行（源码目录用 `cargo run -- ...`）：

| # | 命令 | 期望输出 |
|---|---|---|
| B1 | `workscene.exe --selftest` | 一段 JSON：`windows` 数组非空、`displays` 有项、`diagnostics` 里有"枚举顶层窗口 N 个" |
| B2 | `workscene.exe --m1test` | 末行 `M1 结果：PASS（成功 2 / 失败 0 / 跳过 0）` |
| B3 | `workscene.exe --m2test` | 末行 `M2 结果：PASS（工作空间闭环 + 报告入库 + 级联清理）` |
| B4 | `workscene.exe --m5test` | 末行 `M5 结果：PASS`；第 [2/6] 行应是"桌面未变时自动快照被去重：true" |
| B5 | `workscene.exe --m9test` | 末行 `M9 结果：PASS`；第 [3/3] 行应显示"4 个资源（其中 1 个不可达）" |
| B6 | `workscene.exe --baseline 5` | `成功率 100.0%`（门槛 95%） |

> 这些会**移动并复原**几个受控测试窗口（不是你的应用），可以放心跑。
> 如果 B1–B6 有失败，先别做后面的，把命令和完整输出发我。

## C. 单屏核心功能（人眼判断）

### C1 捕获质量

| # | 操作 | 期望 | 状态 |
|---|---|---|---|
| C1.1 | 打开 Chrome、资源管理器、VS Code、一个文件夹窗口，进「现场捕获」 | 扫描后列出这些窗口；默认全选 | ✅ 本机部分验证 |
| C1.2 | 展开底部「已自动排除 N 个系统/工具窗口」 | 每条有类名、进程、标题、排除原因 | ✅ |
| C1.3 | 打开 Windows「设置」或 Win11 记事本后再扫描 | 它们出现在**排除列表**，原因写明"UWP 打包应用，v1.0 不支持窗口恢复" | ✅ |

**判定**：你日常用的应用都出现在可选列表里；系统窗口不会混进来。

### C2 保存为工作空间

| # | 操作 | 期望 |
|---|---|---|
| C2.1 | 命名 → 保存 | 跳到「工作空间」详情页，顶部显示「应用 / 资源 / 窗口 / 显示器」四个计数 |
| C2.2 | 在详情页拖动画布里的窗口、拖右下角改大小 → 保存布局 | 提示保存成功；刷新页面后位置保持 |
| C2.3 | 「放弃改动」 | 回到保存前的位置 |

### C3 资源（文件 / 文件夹 / 网址）

| # | 操作 | 期望 |
|---|---|---|
| C3.1 | 添加一个文件夹 | 列表出现，显示名是文件夹名 |
| C3.2 | 添加 `https://example.com` | 列表出现，显示名 `example.com` |
| C3.3 | 再添加同一个文件夹 | 报错"该资源已在此工作空间中" |
| C3.4 | 添加 `file:///c:/windows` 当网址 | 报错"网址必须以 http:// 或 https:// 开头" |

### C4 恢复

| # | 操作 | 期望 |
|---|---|---|
| C4.1 | 把窗口挪乱 → 恢复中心 → 选空间 → 开始恢复 | 预览里每项有"识别依据"（例如"按进程路径 + 窗口类名匹配（0.96）"） |
| C4.2 | 恢复完成后看报告 | 每个窗口显示偏差 px；成功/失败/跳过分开计数 |
| C4.3 | 看「历史快照 → 恢复记录」 | 出现这次 run，展开能看到逐条 step；成功的 `error_code` 为空 |
| C4.4 | 报告页点「撤销这次恢复」 | 窗口回到恢复前的位置（因为恢复了"恢复前自动保护"快照） |

### C5 失败路径（这几项最能暴露问题）

| # | 操作 | 期望 |
|---|---|---|
| C5.1 | 打开**两个同一个文件夹**的资源管理器窗口（标题完全相同）→ 保存 → 关掉一个 → 恢复 | 预览/报告显示「窗口匹配存在歧义，已跳过」，`error_code = match_ambiguous`，**不会乱移别的窗口** |
| C5.2 | 保存时开着某个应用 → 恢复前手动关掉它 → 恢复时勾选"自动启动" | 应用被启动并等待窗口出现；找不到窗口则 `window_not_found` |
| C5.3 | 保存时有一个最小化窗口 → 恢复 | 恢复成普通窗口，报告里 `stateRestored=false` 并有文案说明（这是刻意的取舍，不算失败） |
| C5.4 | 把一个窗口拖到另一个**虚拟桌面** → 恢复 | 窗口会被恢复到**当前**虚拟桌面（v1 已知不支持虚拟桌面归属） |
| C5.5 | 保存一个不存在的文件路径（手输 `D:\no-such.md`）→ 恢复 | 预览就标红"路径不存在"；恢复报告里该步 `resource_open_failed` |

## D. 双屏与混合 DPI（**最关键，此前完全没验证**）

准备：一台机器接两个显示器，分辨率/缩放尽量不同（例如 2560×1440 @100% + 1920×1080 @150%）。

### D1 基础双屏

| # | 操作 | 期望 |
|---|---|---|
| D1.1 | 打开窗口分别放在两个屏上 → 捕获 → 保存 | 预览画布里两台显示器按真实相对位置排布（左上/右上取决于你的排列），窗口块落在对应屏内 |
| D1.2 | 挪乱 → 恢复 | 每个窗口回到**原来的那块屏**，而不是都跑到主屏 |
| D1.3 | 看报告 | 每步偏差 ≤ 8px（150% 屏上阈值仍是 8，代码里是 `max(8, 2×scale)`） |

**判定**：只要有一个窗口跨屏错位，就记下你两台显示器的分辨率+缩放+排列，以及报告里那一行的偏差值。

### D2 显示器缺失回退

| # | 操作 | 期望 |
|---|---|---|
| D2.1 | 双屏时保存一个工作空间 → **拔掉/禁用副屏** → 恢复 | 预览顶部出现黄色提示"目标显示器「…」已不在当前环境，已映射到主显示器"；窗口全部落在主屏可见范围内 |
| D2.2 | 报告 | `displayNotes` 里有同样的说明；窗口没有被放到屏幕外 |

### D3 DPI 变化

| # | 操作 | 期望 |
|---|---|---|
| D3.1 | 在主屏 100% 缩放下保存 → 把缩放改成 150% → 恢复 | 窗口仍是"相对工作区的同一位置/占比"，不会跑到屏幕外，也不会尺寸暴涨 |
| D3.2 | 窗口 A 在 100% 屏、窗口 B 在 150% 屏，各自保存后恢复 | 两个窗口都回到各自屏幕的相对位置 |
| D3.3 | 换一个 **System-aware 的老程序**（例如某些旧版工具、部分安装器） | 位置应该正确；若错位，记下程序名+它所在屏的缩放 |

> D3 是这轮最可能暴露问题的地方。`SetThreadDpiAwarenessContext` 已加，但没有实机数据。

**D 段失败时请给我**：显示器数量/分辨率/缩放/排列（截图设置里的显示器页面即可）+ `--selftest` 输出的 `displays` 段 + 报告里那一行。

## E. 快照与异常恢复

| # | 操作 | 期望 |
|---|---|---|
| E1 | 历史快照页点「立即快照」 | 时间线多一条"手动"；带受保护盾牌 |
| E2 | **先恢复一次**（自动快照只对"激活的工作空间"生效）→ 设置里把最小间隔改成 10 秒 → 保持桌面不动 1 分钟 | 自动快照**不增加**（指纹去重生效） |
| E3 | 移动/开关几个窗口，继续等 1–2 分钟 | 出现一条"自动"快照，且不会每秒刷一条 |
| E4 | 设置里把保留改成 2 → 回历史页点「清理自动快照」 | 每个空间的自动快照只剩 2 条；手动/初始/保护快照**一条不少** |
| E5 | 勾选两条快照 → 「比较」 | 显示新增/移除/移动/状态变化计数与明细；只把标点改了的标题不算变化 |
| E6 | 用任务管理器强杀 `workscene.exe` → 重新启动 | 总览页顶部出现横幅"上次 WorkScene 没有正常退出"，带时间与「恢复上次现场」 |
| E7 | 正常用托盘退出 → 再启动 | **不应**出现上面的横幅 |

## F. 系统集成

| # | 操作 | 期望 |
|---|---|---|
| F1 | 设置 → 快捷键 → 改成 `Ctrl+Shift+W` → 按新组合 | 窗口被唤起；旧组合 `Ctrl+Alt+W` **不再**生效 |
| F2 | 快捷键选「关闭」→ 按任意组合 | 不响应 |
| F3 | 设置 → 开机启动打开 → 打开注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 出现名为 `WorkScene` 的字符串值，内容是被引号包住的 exe 全路径，指向当前安装位置 |
| F4 | 注销/重启后登录 | WorkScene 出现在托盘（窗口默认不弹，或按你的实现观察） |
| F5 | 关闭开机启动 → 再看注册表 | `WorkScene` 值消失 |
| F6 | 托盘右键 → 立即快照 | 当前激活工作空间的时间线多一条"托盘快照" |
| F7 | 设置 → 存储 | 数据库/快照/报告三个数字与实际相符（数据目录路径也在页面上） |

> F3/F4 在我这边**写不进去**（沙箱进程写注册表被拒，错误码 5）。这是最需要你确认的一项。

## G. 真实应用基线（可选但推荐）

在同一台机器上（窗口随便开着），执行：

```
workscene.exe --baseline-live 6
```

期望：`真实窗口基线：N/N 通过，成功率 100.0%`，且末尾"报告口径"与独立测量一致。
明细写在 `%LOCALAPPDATA%\WorkScene\baseline\live-*.jsonl`。

**请重点补充这几类样本**（我这边只有 Chromium 系）：
- Office（Word/Excel/PowerPoint）
- VS Code（含打开一个项目）
- Windows Terminal / PowerShell
- 一个多窗口应用（浏览器开 3 个窗口）

若某类应用失败，把它加到清单末尾的失败表里，附 `--baseline-live` 的输出。

## 已知不支持的（不用测，避免误判为 bug）

- UWP / 打包应用（Win11 记事本、设置、计算器、Store 应用）
- 虚拟桌面归属
- 管理员权限应用（UIPI 会拒绝移动，报告里会是 `window_control_denied`）
- U 盘/网络盘拔掉后的资源重定位
- 应用内部未保存的文档状态、浏览器标签页内部状态
